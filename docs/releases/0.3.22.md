# 0.3.22 candidate

OTA protocol 2 replaces the per-chunk status-read loop with notifications of
flash bytes written and read back by the watch. Clients use one authoritative
status read when connecting, including reconnects, and wait for each notified
offset before sending another chunk. ATT write responses remain enabled; one
packet can be queued. At MTU 247, payloads grow from 192 to 236 bytes, reducing
the chunk count by about 19%. Smaller negotiated MTUs remain valid Bluetooth
connections, not a legacy OTA fallback.

The notification sender only publishes changed state/offset snapshots and
retries temporary transmit-buffer failures. Clients resume from checked flash
bytes after a disconnect or missing acknowledgement and reject mismatched
sessions, malformed status and unexpected offsets. Uploading never activates
firmware: INSTALL and KEEP remain explicit on-watch actions. MCUboot validation,
flash readback, trial rollback and emergency bootloader recovery are retained.

The maintained browser and Linux uploaders require protocol 2. Recovery DFU
upload code, gatttool/pexpect dependencies, protocol-1 compatibility, automatic
recovery-address conversion, Nordic init packets/CRC16 and the 200-byte tail
padding workaround are removed. Native `gopine-update-VERSION.zip` packages
contain a MCUboot BIN and a goPine manifest with an image SHA-256. Release and
browser-publication workflows use the native format and select versions 0.3.22
and newer. The stored emergency recovery image and wired provisioning remain.

The installed 0.3.21 receiver needs one final transfer using the preserved local
sender in ignored `build/ota/v1-transition/`. Its prepared command is
`bash build/ota/v1-transition/run-0.3.22.sh`; it uses the goPine address and hci1.
This migration sender is not part of the maintained uploader. The transition
itself still uses the old receiver's speed; protocol-2 throughput can only be
measured on later uploads. No physical speedup is claimed yet.

The larger packet initially exceeded the existing stack regression budget.
Passing the existing packet buffer by pointer instead of returning an array
reduced the selected direct-update core frames to 4,720 bytes, plus the existing
2,048-byte reserve, within the 8,192-byte task stack. Reserved RAM remains
23,156 bytes and the heap region 42,380 bytes. These are selected-path regression
budgets, not runtime free-memory measurements.

Validation passes: race-enabled Go tests and vet, eleven C ASan/UBSan suites,
the pinned-host integration test, Python package/uploader/HTTP/release/Pages
staging tests, all browser tests, and the TinyGo BLE build/resource gate.
The real-host test uses MTU 247 with 27-byte incoming HCI ACL fragments and checks
236-byte packets, required subscription, one-packet backpressure, no premature
flash acknowledgement, changed-status notifications and retry after exhausting
the notification buffer pool. Browser and Python tests check missing
acknowledgements, resume, protocol-1 rejection and malformed status. Both package
readers validate the built ZIP; the local transition sender passed an offline
protocol-1 test without making a Bluetooth connection.
