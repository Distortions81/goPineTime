# goPine 0.3.31 memory and exclusive-update candidate

Firmware Update now suspends notification handling, music/weather work,
alarm delivery, vibration, pairing overlays, and settings saves. Bluetooth
transfer handling, watchdog servicing, power checks, and input/Cancel remain
active. This prevents a due timer from replacing the update screen and cancelling
the transfer. Suspended ANCS records no longer wake the loop repeatedly.
Cancellation restores normal services and delivers overdue timers. Retryable
errors remain in exclusive mode until the user retries or leaves.

The OTA receiver reuses one 256-byte scratch buffer for trailer checks, chunk
readback, image hashing, and installation verification. Reset clears metadata in
place instead of allocating a receiver-sized temporary. Its packet and receiver
workspace is allocated on first use and retained for later sessions.

Notifications recycle four stable message slots and move only byte indices when
inserting or dismissing messages. Completed ANCS responses are decoded directly
into a reserved mailbox slot. Empty/invalid input cannot evict a valid message;
shorter replacements clear old text. Notification capacity and text limits are
unchanged, and the inbox stays separate from OTA storage.

This candidate also includes the [0.3.30 display and navigation changes](0.3.30.md).

## Measured memory and validation

- ARM updater object: 560 → 48 bytes before first OTA. Its lazily allocated
  workspace is 536 bytes, so retained storage after first use is 584 bytes
  versus 560 previously. This trades 24 retained bytes for reuse and removal of
  transient allocations; it is not a 512-byte saving during an update.
- Checked OTA stack path: 4,744 → 3,928 bytes. Notification path:
  4,752 → 4,520 bytes. Notification state remains 680 bytes.
- Reserved RAM remains 22,132 bytes and the heap region remains 43,404 bytes.
  The task stack remains 8,192 bytes. The largest selected path plus the
  existing 2,048-byte deeper-call reserve is 7,968 bytes.
- A controlled build with fixed version/date/time reduces code plus data by
  4,228 bytes. The final packaged MCUboot image is 296,292 bytes.
- Go tests, race detector, vet, 12 C sanitizer suites, native NimBLE integration,
  resource-checker tests, and the exact ARM ELF gates pass. Inbox fuzzing passed
  1,537,333 executions. Repeated OTA and notification lifecycle tests allocate
  zero after setup; the new TinyGo build gate reports no heap allocation sites
  in the receiver, validation-with-scratch, or inbox paths.
- Production-loop tests exercise an overdue timer, pending vibration and PIN
  overlay, background callbacks, power polling, Bluetooth host pumping,
  unchanged-screen rendering, and cancellation/resumption. Native host tests
  cover suspended ANCS wakeups and 100 phone/weather/OTA mode cycles.

These are regression checks, not a full mixed Go/C stack bound or physical
free-heap measurement. The largest selected stack path has only 224 bytes beyond
its deeper-call reserve; the stack and heap budgets were not relaxed.

The OTA window remains two packets. Measured fixed-width queue layouts are
500/996/2,484/4,964 bytes for 2/4/10/20 packets. The existing shared phone/OTA
payload is 984 bytes, so four slots would add only 12 raw bytes, ten would add
1,500, and twenty would add 3,980 before linker alignment. Enlarging the window
still needs protocol/backpressure tests and device throughput measurements.
