# goPine 0.3.33 persistent battery status

A compact percentage and battery icon now appear at the top right on every
screen, including pairing, alarms, firmware updates, and charging overlays.
The icon shows a bolt only during active charging. Low battery uses the warning
color; external power uses the accent color. Both display themes are supported.

The Settings battery footer and the larger clock-only indicator are removed.
Settings save/error notices remain. The status occupies the unused top band
above existing headers, so titles and touch controls keep their space. The small
numeric glyphs use a 55-byte immutable string in flash, with no new font object
or persistent RAM buffer. Power changes now invalidate pairing-screen frame keys
too. Charging overlays have matching rendering/frame-key priority.

No new power polls, screen-awake behavior, or animation were introduced. It uses
the existing power readings, sleep behavior, and strip renderer.

## Validation

Go tests and vet pass. Tests check all pages and overlays in both themes, header
separation, battery-change invalidation, charging versus external power, clamping,
footer removal, and retained settings notices. Existing pixel-equivalence and
zero-allocation rendering checks pass. SDL previews of Settings, pairing, updates,
and both themes were inspected under `build/previews/0.3.33/`.

The BLE ARM build, exact ELF resource/allocation gates, and package validation
pass. The image is 296,036 bytes. Reserved RAM remains 22,132 bytes, leaving a
43,404-byte heap region. The largest selected stack path plus its unchanged
2,048-byte reserve uses 8,000 of 8,192 bytes. These are regression budgets, not a
physical free-heap measurement or a full mixed Go/C stack proof.

## Watch transfer

Uploaded through the in-app updater on 2026-10-11 using hci1. The watch received
all 296,036 bytes and verified the image. The transfer used acknowledged writes,
a one-packet window, and 236-byte payloads: 177.9 seconds total, 173.2 seconds
for data, and 0.9 seconds for verification. The initial sandbox-blocked attempt
sent no firmware; the successful attempt required host Bluetooth access.
INSTALL, boot, and KEEP have not been user-confirmed.
