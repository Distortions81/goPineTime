# goPine 0.3.34 Bluetooth shutdown cleanup

Turning Bluetooth off now explicitly disables the shared CCM/AAR encryption
and address-resolution peripheral. The previous shutdown stopped the radio,
timer, RNG and crystal but could retain this peripheral's enabled state.
Startup-failure cleanup uses the same shutdown sequence. Pairing and encryption
during active connections are unchanged.

The actual pinned nRF52 PHY reproduces the omission in a register-memory host
test. The fixed sequence clears the enable register and permits repeated
restarts. This establishes incomplete cleanup; the effect on sleep current and
battery runtime still requires watch measurements. See the
[power investigation](../power.md#bluetooth-off-investigation-2026-10-16).

This release also includes the changes since public release 0.3.16: two paired
devices, Apple notification support, pairing/reconnect fixes, protocol-2 OTA
with a negotiated two-packet pipeline, reduced memory use, Display/Bluetooth
UI cleanup, and a battery indicator on every screen. Notification delivery has
been confirmed on hardware; full physical InfiniLink completion remains
unverified. Normal updates require goPine 0.3.22 or newer; older firmware needs
its original transition sender or a wired installation.

## Validation

Go tests and vet, PHY and NimBLE host integration tests under ASan/UBSan,
and the BLE ARM build pass. Simulated idle checks cover an hour after shutdown,
including after encrypted phone traffic. The exact release ELF passes the
resource/allocation gates and the package passes uploader validation.

Image size: 296,036 bytes. Reserved RAM: 22,132 bytes. Heap region: 43,404 bytes.
These are static budgets, not measured current or free-heap figures.

## Watch transfer

The initial attempt on 2026-10-16 stopped before connecting because `hci1`
was missing; no firmware was sent. USB/sysfs inspection identified the TP-Link
UB500 (`2357:0604`, controller `3C:78:95:44:D8:FD`) as `hci0`; MediaTek remained
disabled. The in-app upload was then started through the verified TP-Link.
The watch received all 296,036 bytes and verified the image. Transfer used a
two-packet window, writes without response and 236-byte payloads: 44.0 seconds
total, 39.6 seconds for data and 1.0 second for verification. On 2026-10-16 the
user confirmed installation, boot and KEEP. They plan to leave Bluetooth off
and check the battery on 2026-10-17; post-update runtime is not yet measured.
