# goPine 0.3.35 sleep candidate

Stops the hardware random-number generator that TinyGo starts during boot and
otherwise leaves running even with Bluetooth never enabled. Cleanup also
resets the driver's remembered start flag so a later RNG read can restart.
Active and draining Bluetooth sessions retain RNG ownership.

Removes the fixed one-second watchdog wake cap. Idle keeps the existing
one-quarter-reload-period safety margin and four-minute RTC bound. With a
five-second watchdog, watchdog-only wakeups fall from once per second to once
per 1.25 seconds. Earlier application deadlines and GPIO wakeups retain priority.

The user reports roughly 50 hours to low battery on 0.3.34 asleep with Bluetooth
off. The boot RNG leak is confirmed in source and compiled code, but its share
of that drain is unmeasured. See the [sleep audit](../power.md#sleep-pass-2026-10-22-candidate-0335).

## Local validation

- Go tests and vet pass.
- The actual TinyGo RNG driver reproduces the boot leak in a host register
  model; cleanup, 20 restart cycles, and the busy-radio guard pass.
- NimBLE primitives, host integration, and the actual PHY tests pass ASan/UBSan.
- PineTime standalone and BLE ARM builds pass. The exact BLE ELF passes memory,
  allocation, and RNG-call-site checks; uploader package validation passes.
- The RNG shutdown and driver-flag writes were checked in compiled ARM code.

## Watch transfer

On 2026-10-22, the prepared protocol-2 package was uploaded in-app through
the configured TP-Link adapter `hci0` to `C9:9E:15:7A:69:B4`. The watch received
all 296,132 bytes and verified the image. Transfer used a two-packet window,
writes without response, and 236-byte payloads: 55.5 seconds total, 41.8 seconds
for data, and 1.0 second for verification.

The uploader instructed INSTALL followed by KEEP after reboot. Transfer
validation is confirmed; installation, boot, and KEEP have not been confirmed
by the user.
