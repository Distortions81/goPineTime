# 0.3.21 candidate

After receiving 0.3.20, the user entered the phone pairing code but pairing did
not complete. INFO showed **No saved phone**. That proves no bond was saved;
it does not identify whether the code exchange, encryption, or identity
distribution failed.

The investigation reproduced a permission mismatch: after code authentication
and encryption succeeded but before identity distribution finished, feature
writes returned ATT **Insufficient Authentication** solely because the bond
was still pending. The pinned reference's `ble_att_svr_check_perms` checks link
encryption/authentication/key size independently of bonding. A new real-host
test reproduces the erroneous CTS retry response before this change.

ATT writes now require authenticated encryption with 16-byte keys at receipt.
Their data is retained in the existing bounded mailboxes, but time/weather,
notifications and music metadata are not delivered to Go until bonding finishes.
Failure clears pending data. Connected status, ANCS discovery and outgoing
music controls still require a completed bond. Pending mailboxes do not force
an input-wait spin during identity exchange. No pre-encryption payload is
retained or promoted to trusted data. The tests cover successful delivery and
discard after a peer aborts identity exchange. This is a demonstrated host
permission defect; its role in the physical iPhone stall is still an inference.

The PIN screen now shows the current security stage and completed passkey
rounds out of 20. INFO retains the last observed stage alongside existing S/D
errors when the exchange fails or disconnects. The pinned NimBLE procedure is
read under its host lock only after dispatch has unwound. No keys, nonces or
private scalars are exported, and no logging buffer, flash write or polling timer
is added. Stage changes redraw only the status text's strips; pixel comparisons
verify no stale text remains, avoiding full-screen rendering on each SMP round.
Forget Phone clears the retained stage.
SMP timeout status 13 now reads **Pairing timed out**.

The real-host test now supplies incoming HCI ACL packets in 27-byte fragments,
matching the production controller without data-length extension. All 20 code
rounds, DHKey checks, encryption and identity distribution still pass. It
asserts each displayed stage/round and retention after a wrong code/disconnect.
A 31-second stalled exchange clears the PIN and preserves its phase and timeout
error. An encrypted Battery read before identity distribution succeeds with
the existing policy; the suspected battery/bond-ordering failure is ruled out
at the host level. These checks do not simulate the physical nRF radio or iOS.

Validation: race-enabled Go tests, vet, eleven C ASan/UBSan suites, the real
pinned-host integration test, and the BLE build/resource gate pass. New PIN and
timeout screens were rendered and visually checked at 240×240.
