# goPine 0.3.29 memory candidate

The Bluetooth and OTA work was checkpointed and pushed as `b2b110d` before this
memory pass. Upload speed work is deferred at its existing two-packet window.
No firmware was uploaded during this pass.

## RAM changes

The ARM linker reports 2,048 fewer reserved RAM bytes than 0.3.28. The heap region
grows from 41,356 to 43,404 bytes. This measures statically reserved memory, not
physical free heap during use. The 8,192-byte task stack, stack safety reserve,
two saved paired devices, three OTA connections, eight mbufs, four shared ACL
credits and 5 KiB NimBLE allocation arena remain unchanged.

| Static storage | Before | After | Saved |
| --- | ---: | ---: | ---: |
| goPine GATT definitions and UUID literals in RAM | 784 B | 0 B | 784 B |
| ATT prepared-write entry metadata | 768 B | 96 B | 672 B |
| Phone, weather and OTA payloads plus phone metadata | 1,640 B | 1,032 B | 608 B |

The individual objects save 2,064 bytes; linker alignment accounts for the
16-byte difference from the final reserved-RAM improvement.

GATT definitions are immutable and now remain in flash. Their value-handle
pointers still refer to writable storage; attribute ordering and handles do not
change. Prepared-write entries are capped at eight because every entry retains
at least one buffer from the existing eight-buffer pool. The previous 64-entry
reservation could never be filled. Queued-write support remains available.

Phone feature payloads, standalone weather payloads and OTA packets share one
mode-specific storage area. Connection metadata and ANCS state remain separate.
Mode changes require completion of the prior host shutdown. Late events, busy
start attempts and stale update-status publications cannot corrupt another mode.
Standalone weather retains accepted data through disconnect and reconnect.

## Temporary heap allocations

The SPI flash driver now retains a seven-byte command/reply scratch area on its
open flash object. Synchronous DMA completes before those bytes are reused;
controller polling does not use external SPI flash. TinyGo's allocation report
falls from nine allocation sites in the driver to two, both associated with
opening/waking flash. Command creation, status polling and write-enable operations
no longer allocate on each call. Watchdog servicing, bounds checks, write/readback
verification and error handling remain in place.

For the 296,796-byte baseline image, an operation-count model gives at least
22,284 eliminated small allocations through verification, even if every busy
poll returns immediately. This is cumulative allocation churn, not an additional
22,284 objects retained at once or a physical throughput measurement.

## Validation

The resource report now lists the twenty largest linked static RAM objects so
future changes expose their main consumers. Existing heap and stack limits are
unchanged. Validation includes ARM linking and package verification, Go race tests
and vet, port sanitizers, and the pinned NimBLE host harness.

New host regressions exercise 100 Phone/weather/OTA transitions with queued data,
busy starts, stale status and connection events. Actual ATT Prepare/Execute writes
fill the shared mbuf pool, verify cancel and disconnect cleanup, and execute valid
fragmented commands. Existing multi-device pairing, notification, service-cache
and OTA tests continue to cover the surrounding behavior. Physical memory and
InfiniLink Home completion remain unmeasured/unconfirmed.
