# goPine 0.3.30 display and navigation candidate

Settings now groups Time & date, Bluetooth, Display, and Firmware update.
Bluetooth replaces Phone and has separate Turn on / Pair a device, Paired
devices, and Turn off controls. Opening a feature or viewing paired devices
does not start or stop its shared connection.

Apps uses six equally sized tiles: Alarms, Stopwatch, Timer, Music, Messages,
and Weather. Messages no longer depends on a small header shortcut. Weather
is visibly disabled and ignores taps while its companion delivery is unavailable;
its cached data and protocol implementation are retained.

Display includes a saved Dark/Light theme, High/Low/Medium backlight, Touch
wake, and Rotation. PineTime's three fixed backlight levels use its existing
active-low GPIO channels, with no PWM resource. Sleep disables every channel
and wake restores the selected brightness. The light palette applies to text,
icons, controls, pairing, and charging before antialiasing.

The settings struct remains 28 bytes and journal records remain 160 bytes.
A previously reserved byte stores the new choices. Existing records select
Dark and High and retain alarms, timers, and Bluetooth preferences.

## Validation

- Go tests with the race detector and `go vet ./...` pass.
- Tests cover navigation and inert gaps, disabled Weather, all six persisted
  display combinations, interrupted settings writes, brightness across
  sleep/wake, and full-frame versus packed-strip pixels in both themes.
- Warm drawing and frame identity paths retain zero per-frame allocations.
- SDL previews were inspected in both themes, including pairing and charging.
- The BLE ARM build and OTA package verification pass without relaxing budgets.

The linker reserves 22,132 RAM bytes, leaving a 43,404-byte heap region, unchanged
from 0.3.29. Rendering retains its 2,880-byte strip. The task stack remains
8,192 bytes; the largest checked path plus the existing 2,048-byte deeper-call
reserve uses 7,960 bytes. These are selected-path regression checks, not a
whole-program stack proof or a physical free-heap measurement.
